## Overview

Data Management System

The second project is to build a system that manages a type of data of your choice, allowing users to create, read, update, and delete customizable objects. The application will utilize the concepts learned in Java, such as data types, variables, control flow, loops, methods, scopes, arrays, ArrayLists, Object-Oriented Programming (OOP), exception handling, file I/O, inheritance, polymorphism, abstract classes, interfaces, design patterns, and test-driven development.

The data management system will be a command-line interface (CLI) program that runs in the console without a graphical user interface (GUI). Users will interact with the application by typing commands and receiving text-based output.

The goal of this project is to show off design patterns and inheritance among many objects! Pick what type of data you plan on building around accordingly. Choose from:
- Employee management system used to track a variety of features of an organization's employees (title, salary, hire date, etc.) 
- Car dealership system that stores business information about various cars (make, model, sale date, etc.)
- Zoo management system, with relevant information for the keepers for organizing their zoo (carnivore/omnivore/herbivore, group/solitary, etc.)
- Data type of your choice!

***You will work individually on this project***.

> ❗️ As a reminder, General Assembly has a zero-plagiarism policy. ***Your project's code must be substantially yours***. Do not copy code from similar projects or other sources. However, using code from the internet to accomplish generic tasks is okay - for example, a line of code that replaces a character at a specific position in a string.

## Technical requirements

### MVP

> ✅ Any items marked incomplete in this section will require you to use your one redo to re-submit them. Your app must fulfill the below requirements.

- Design unit tests for all app functionality.
- Design and use data objects that are created via a design pattern and inherit from at least one other class.
- Create objects in memory from a saved text file.
- Update the text file to reflect changes to objects.
- Implement at least one Singleton pattern (data manager, logger, etc.).
- Implement at least one Builder or Factory pattern, as appropriate to your objects. 
- Create at least three interfaces for your objects to inherit from.
- Create at least two abstract classes for you objects to inherit from.
- Allow users to do the following:
    - Create complex and custom objects.
    - Delete specific objects.
    - Find objects based on their properties.
    - Update existing objects.
    - Close the application. 
- There is a runnable JAR file that allows users to download and run the project.

> ✅ More than two items marked incomplete in this section will require you to use your one redo to re-submit them. If two or fewer items are marked incomplete, the project is considered passing. Your app must fulfill the below requirements.
